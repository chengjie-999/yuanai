# 聊天界面信息架构企业级重构（2026-11-08 用户立项：模式切换丝滑化 + 输入区去冗余）

## 现状问题（用户实测）

1. 「工作/娱乐」与「云端/自动/本机」两个分段开关相邻，语义重叠（娱乐=强制云端），用户感知冗余
2. 数据集切换几乎不用，却占工具行位置
3. 模型下拉折叠态显示模型全 ID，太长
4. 推理强度（快答/深思）是低频设置却常驻工具行，应子页化
5. @面板/后端切换之间的过渡不丝滑（切换后无反馈、状态不同步）

## 设计原则（企业级信息架构）

- **高频动作近手，低频设置收纳**：输入区只留每次对话可能用的；任务级参数（模型/推理/位置/数据）统一收进「任务设置」弹层
- **自动路由优先，手动开关兜底**：chat_mode_router / route_chat_backend 关键词路由已是主旋律——UI 引导用户「直接说需求」，手动开关是显式覆盖手段而非常驻仪表盘
- **切换必有反馈**：任何模式/后端/模型切换，即时 toast/气泡提示当前生效配置，防「不知道现在跑在哪」

## 方案

### A. 自动化归属（决策：维持独立 Agent）

- **维持现状**：automation 保持唯一 react 子 Agent（浏览器会话/截图流/10s 心跳/停止联动等基建已成熟；豆包 pro 多模态+浏览器工具生态已适配）
- **不做 CC skill**：CC 走 DeepSeek 网关+审批流，浏览器长任务塞进 CC 循环=状态管理倒退
- **挂账**：给 CC 加轻量浏览器 MCP（Playwright MCP 式）供顺手开网页，与专用自动化两线并存（P2 愿景）

### B. 输入区重构：工具行左高频右收纳

```
[回形针(附件/数据集) @指定 图片 语音 朗读 下载]   [⚙ 任务设置]
```

- **左动作群（高频，保持不变）**：回形针（含数据集上传+引用——数据集入口并进来，弱化独立按钮）、@、图片、语音、朗读、下载（小屏隐藏）
- **右设置群收敛为单个「任务设置」弹层**（点击齿轮弹出，四合一）：
  1. **模型**：下拉显示**简称**（DeepSeek V4.1 / 豆包 2.0 Pro 等，全 ID 进悬浮提示），折叠态输入区不显示模型名——只显示当前简称小字或干脆不显示
  2. **推理强度**：快答/深思（从工具行移入——低频设置子页化，用户拍板方向）
  3. **执行位置**：自动（推荐）/ 云端 / 本机（从工具行移入；自动路由为主，这里做显式覆盖）
  4. **数据集**：当前选中数据集显示+选择+清除（从工具行移入；注入输入框的 `[数据集 #id]` 引用逻辑不变）
- **工作/娱乐**：保留为工具行上唯一的分段开关（产品模式=人设级决策，值得常驻）；娱乐模式自动=云端（后端已强制），弹层里的执行位置在娱乐模式下置灰

### C. 切换丝滑专项

1. **切换即时反馈**：切模型/推理/位置/娱乐 → 输入框上方短暂提示条「已切换：本机执行」2s 消失（复用 flashNotice 机制）
2. **@面板状态实时性**：本地 Agent 在线状态在 @面板中实时更新（现有 AgentStatus 10s 轮询延用；离线置灰已有）
3. **首次引导**：新用户输入区工具行只显示高频五项+齿轮，任务设置弹层首次展开时轻量提示「一般不用管，直接说需求即可」
4. **backend_event/mode_event 联动**：模型主动切换时弹层状态同步刷新（现有事件已通，弹层组件消费即可）

### D. 实施顺序

1. **E1 弹层骨架**：任务设置弹层（模型简称化+推理强度+执行位置+数据集四合一）+ 工具行右收敛为齿轮
2. **E2 工作/娱乐与执行位置去重**：娱乐模式弹层位置置灰 + 切换反馈提示
3. **E3 数据集入口弱化**：独立按钮移除并入回形针/弹层
4. **E4 移动端**：弹层在手机上为底部抽屉（bottom sheet）

### 挂账（不阻塞）

- CC 浏览器 MCP（P2）
- 推理强度按任务自动建议（模型自主 set 工具已存在，前端展示联动）
- 模式切换动画过渡（0.12-0.18s 微交互规范内）
