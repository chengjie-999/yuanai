## 二、手机使用习惯设计原则（本方案基线）

1. **拇指热区**：高频操作（发送/语音/上传）在屏幕底部输入区（现状已符合，不推翻）；弹层/浮层一律贴底（bottom sheet），不做居中卡片
2. **触控目标 ≥44px**：工具行/操作行图标按钮手机端统一加高
3. **输入框字号 ≥16px**：防 iOS 聚焦缩放（必改）
4. **安全区**：`--safe-top/--safe-bottom` 变量已接入，新增底部元素一律复用
5. **老内核兼容纪律（新立，X5 连踩两轮）**：新代码禁用 `inset` 简写、`100dvh` 单声明——一律显式四边定位 + `100vh` 先行 `100dvh` 覆盖（CSS 双声明天然 fallback，JS inline 单声明不允许）
6. **操作去 hover 化**：手机上不依赖 hover 预判——需要 hover 才能发现的交互（操作行、删除按钮）改为长按/显性化

## 批次 2：长按交互体系 + 生成中排队（2026-11-17 立项，用户拍板「先仔细设计再登记」）

**状态**：✅ 已登记，待开工。

### 一、实测问题盘点

1. 微信 X5：块长按 → 我们的菜单 + 微信原生菜单 = **两组菜单**；HTML 块还出现**卡住**（CSS 抑制无效，X5 原生菜单拦不住）
2. **HTML/SVG 单击放大后，消息长按不生效**（查看器交互后状态残留，疑点见下）
3. 用户要求：**块长按与消息长按区分**（块长按不该弹通用消息菜单）
4. 生成中想发消息只能先停止 → 需要**排队自动发送**

### 二、长按菜单三层设计（互斥触发）

| 层级 | 触发区 | 菜单内容 |
|---|---|---|
| L1 消息通用菜单 | 气泡文字/内容区（不含块） | 复制/朗读/点赞/点踩/举报/重新生成/修改/继续生成 +（消息含块时）下载 HTML / 下载图表 PNG |
| L2 块级菜单 | HTML/SVG/Mermaid 块区域 | 放大 + 块专属下载（块功能不进通用菜单的主区） |
| L3 查看器 | 放大后的全屏查看器内 | 本期只修「放大后长按不生效」bug，不加新菜单 |

**互斥机制**：块容器统一标 `data-block-area`；消息行 onTouchStart 命中块内即不启动行计时器；块长按计时器只挂在块容器上（新通用组件 `BlockLongPress`：500ms 计时 + 滑动取消 + 松手补发 click 吞掉一次，复用 MobileBubbleMenu）。

**微信策略（UA MicroMessenger 判定，原生菜单无法抑制，避让而非对抗）**：
- 块区域长按：**不弹我们的块级菜单**——微信原生菜单（保存图片等）单独出现，不叠加、不卡住；块下载功能经 L1 通用菜单兜底可达
- 消息文字区长按：仍弹我们的通用菜单（文字选择已禁，微信不弹原生）
- HTML iframe 注入脚本：微信内**不注入长按桥接**，只保留单击放大桥接
- 非微信浏览器：块长按弹块级菜单（完整功能）

### 三、查看器打开时长按应禁用（用户澄清：不是「长按失效」，是让它不生效）

- **现状**：放大查看图片/HTML 时，长按查看器会弹出**与消息长按相同内容的菜单**——根因=HtmlViewer/SvgZoomViewer 渲染在气泡行 DOM 内，查看器上的 touch 事件冒泡到行级 onTouchStart 计时器，500ms 后触发通用菜单
- **修法（在现有查看器基础上改，不重写）**：
  1. `ZoomViewer`（ZoomableImage.tsx 导出，所有查看器共用底座）挂载/卸载时置模块级标记 `isZoomViewerOpen()`——消息行与块级（BlockLongPress）长按计时器检查该标记，置位时直接跳过（查看器内长按彻底不生效）
  2. `HtmlViewer` 用**去桥接 srcDoc**：缩放脚本（wheel/双击）保留，点击放大/长按菜单桥接脚本**不注入**——查看器内不再发 `__yuanZoom`/`__yuanMenu` 消息
  3. 图片查看器（ZoomableImage 在 ChatPage 顶层）如实测也复现，同一标记天然覆盖（共用 ZoomViewer）

### 四、生成中消息排队（wait-to-send）

- **交互**：loading 时输入后 Enter = **排队**（现行为=停止，改为排队）；「停止」按钮保留显式停止；排队提示「消息已排队，AI 回答完后自动发送」
- **队列**：`pendingSendQueueRef [{text, images}]`，上限 5 条；排队即清输入框
- **出队**：流完成回调 + 停止生成后（AI 空闲即发）→ 链式逐条自动发送；drain 防重入守卫；**切会话清空队列**（防串会话）
- **并存**：与语音转录排队（flushVoiceTranscripts）互不干扰；自动朗读/保存链路照常
