# CC 桥接体验修复方案（2026-11-09 立项，来源：云端指派本地全流程实测）

**背景**：一次「云端 → 本地 Claude Code」真实指派会话暴露了桥接链路的系统性体验问题（完整现象与根因见会话分享 ae2054e1 与 2026-11-09 会话记录）。用户拍板：这次对话体验太差，必须修。

**愿景锚点（用户强调：愿景是本项目灵魂）**：本项目愿景 = **「手机定计划、电脑执行」**——对话统一入口、本地 Agent 为执行枢纽、终端式体验（P1-P5 已全落地：yuan 终端 / 对话内嵌终端面板 / 桌宠 / 移动响应式），观测面 O1-O3 已落地（/agent/activity 元数据上报）。本次会话本质是愿景**执行侧（电脑执行）**的压力测试：执行基建裸奔 + 身份管理漏风 + 观测面没有在对话里消费。修复 = 给愿景的执行侧补体验基建，不是推倒重来。

**用户路径复盘**（按时间序）：
打开 CC 私聊 → 兜底冒充答数轮（身份分裂）→ 真 CC 上线但工作目录在沙箱（改代码无从下手）→ 让 CC 改代码 → 委派锁死 6 次 → 每次委派弹空终端窗口 → 更新崩 DLL 零进度 → 重启 → 计划机制无 CC 通道 → 分享出去的角色全消失 → 让 CC 读分享链接又被联网收口误伤。

**结论**：桥接基础设施（会话锁/子进程/更新器）裸奔 + 身份管理（自报/落库/UI/分享）四处漏风 + 观测面（O1-O3）未进对话。修复按 P0→P3 四批执行。

## P0 桥接可靠性（体验崩坏的直接原因，最优先）

| # | 修复 | 具体做法 | 范围 |
|---|------|---------|------|
| 1 | **会话锁自愈** | claude_bridge 单飞锁加看门狗：上一请求超过 N 分钟（默认 10，可配）→ 强制杀 claude 子进程 + 复位锁 + 返回人话错误「上一任务卡死已终止，请重试」；「正在处理上一请求」提示带上已等待时长。复用 stop_request 通道让用户「停止生成」能杀掉挂起委派（云端 B1-11 基建已就绪，桥接分支接入即可） | Agent（重打包） |
| 2 | **委派静默化** | claude_delegate.py:110 与 claude_bridge.py:360 的 spawn 加 `creationflags=CREATE_NO_WINDOW`（Windows）；CLI 分支失败时把 stderr 末 2000 字带进返回——失败不再无日志、不再弹空窗口 | Agent（重打包） |
| 3 | **更新器自愈** | 启动/更新前清理 `%TEMP%\_MEI*` 残留（try/except 静默）；更新失败给人话报错（「更新包解压失败，可能被杀软拦截…清临时目录重试或去设置页重新下载」）；「检查更新」失败不再静默 | Agent（重打包） |
| 4 | **退出清子进程** | 托盘退出时 tree-kill 自己 spawn 的 claude 子进程（登记 PIDs，递归杀）——根治「只有重启才释放锁」 | Agent（重打包） |

## P1 身份管理（信任崩塌的根源）

| # | 修复 | 具体做法 | 范围 |
|---|------|---------|------|
| 1 | **回退提示重写** | claude-stream 回退人设改为「你是云端兜底，不是本机 Claude Code」：第一句必须自报身份（「本地 Claude Code 离线，我暂为云端应答」）；明确「你没有本机任何信息（工作目录/文件/进程），本机相关问题一律如实说不清楚并引导」；结尾引导用户等本地在线或去设置页检查 | 云端（部署） |
| 2 | **兜底落库独立说话人** | 兜底消息 sender 不再记 claude（现前端 placeholderSender 混记），新增 `cloud_fallback` 身份 → 视图滤波不会把兜底的话塞给真 CC 当「自己之前说的」 | 前端 + 云端 |
| 3 | **私聊窗身份徽标** | CC 私聊窗顶部显示桥接状态徽标（在线=棕「Claude Code 本机」/ 离线=灰「云端兜底」），复用 @ 面板在线状态数据源 | 前端 |
| 4 | **分享页角色显示** | `api/v1/chat/share.py` 读 sender 列（优先级 列 > META.s > 缺省），气泡上方加说话人标签 + 身份色（对齐聊天界面：蓝=小元 / 棕=Claude Code / 灰=云端兜底）；兜底身份正确渲染；C5 标识保留 | 云端（部署）+ 静态渲染 |
| 5 | **回退首句自报** | 回退提示强制首句身份声明（并入 #1） | — |
| 6 | **CC 读自家分享链接（2026-11-09 追加）** | /claude-stream（及桥接转发）检测消息中的 cjyuanai.cn `/api/v1/share/{sid}` 链接 → 云端读自家静态文件 → 纯文本注入消息上下文（标注已展开）→ CC 直接读到。CC 零新增联网能力、安全面零新增（云端只读自家文件）；读不了/未分享人话提示。比放开 curl/WebFetch 干净（现 WebFetch/curl 全禁、cc_search 只管搜索，「读自家公开页」被联网收口误伤） | 云端 |

## P2 @ 对话粘性（「不私聊只能一轮」）

| # | 修复 | 具体做法 | 范围 |
|---|------|---------|------|
| 1 | **@ 粘性定向** | 主对话 @Claude/@自动化 后进入「定向对话期」：后续消息默认继续发给同一目标，直到换 @ 或点输入区「退出定向」徽标（微信式 @人=持续对话）。前端 activeTarget state（会话级 localStorage）+ 输入框目标徽标；后端 target 通道已直通零改动。统筹是默认无需粘性 | 前端 |
| 2 | **计划白名单报错人话** | plan skill 校验失败时错误信息说清「仅支持数据分析/数据采集」；plan 机制暂不加 claude_code skill（执行器本地跑 CC 委派需桥接在线+审批，复杂度高，二期再议） | 云端 |
| 3 | **兜底引导话术** | 回退提示补一句「本地 Agent 上线后我自动转回本机 Claude Code；着急可去设置页检查 Agent 状态」（并入 P1#1） | — |
