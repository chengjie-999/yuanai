# 网页对话双形态：对话式 AI + 长任务智能体独立窗口（2026-11-13 v2 设计登记）

**来源（用户原话 2026-11-13）**：艾特切换移到侧边栏「新对话」上面，各智能体横向平铺，点击切换各自对话；主对话 AI 以对话式 AI 方式与用户互动（用户交互的主要窗口），不再群聊，而是向其他智能体发送消息，思考与工具调用上加智能体运行状态（展示形态自行设计）；可调用本地智能体。CC 作为独立智能体——独立上下文和会话、可切换、受统筹监控和领导，不需要对话式 AI 布局，消息以智能体最舒服迅速的方式呈现，点赞/点踩/语音/重新生成可以不要，其他长对话任务的智能体同理。**核心区分：对话式 AI 用于用户交互和统筹，智能体用于干活。**借鉴成熟产品设计。

**状态**：v2 设计登记，待用户拍板决策点 D1-D5 后分期开工。

## 1. v1 → v2 演进

v1（2026-11-12 登记）目标「去群聊化：每智能体独立上下文 + 独立执行窗口」，窗口是主对话下挂的「子窗口」（从统筹消息点开）。v2 用户重定交互模型：

| 维度 | v1（已弃） | v2（本次拍板方向） |
|------|-----------|------------------|
| 窗口入口 | 主对话里点开子窗口 | **侧边栏一级入口，与主对话平级切换** |
| 窗口形态 | 统一对话布局 | **两种渲染协议**：对话式 AI（气泡）vs 长任务智能体（执行日志） |
| CC 定位 | 窗口=纯 UI 容器（决策点 C） | **一级智能体**：独立上下文+会话，受统筹监控领导（决策点 C 已定） |
| 智能体输出 | 逐条进主对话群聊流 | 只在执行窗口 + 主对话挂任务卡摘要 |

v1 的复用资产盘点（§3）与「统筹仲裁」原则保留。

## 2. 产品概念：两类智能体、两种窗口

| 维度 | 对话窗口（conversation） | 执行窗口（agent） |
|------|------------------------|------------------|
| 智能体 | 小元AI（统筹，云端） | Claude Code、自动化（未来更多长任务智能体） |
| 职责 | 用户唯一交互入口：意图路由→委派→汇总 | 干活：独立上下文执行长任务 |
| 布局 | 气泡对话式（现状） | **执行时间线**（指令块/思考折叠/终端面板/紧凑工具卡/审批卡） |
| 气泡操作 | 复制/点赞/点踩/举报/重新生成/继续生成/朗读 | 仅复制（命令/结果级）+ 折叠 + 停止；**无点赞点踩语音重生成** |
| 语音 | 气泡朗读 ✅ / 通话 ✅ | ❌ |
| 记忆折叠 | ✅（用户事实） | ❌（执行日志非用户事实） |
| 追问建议 | ✅ | ❌ |
| 历史截断 | 60 条（现状） | CC 不截断 / automation 200 条（现状） |
| 输入区 | 现状（@ 委派 + 附件 + 语音等） | 精简：任务指令 + 停止 |

借鉴对象：**豆包**（智能体平铺切换、每智能体独立历史——用户描述形态的同款先例）、**Cursor**（Chat/Agent 双形态并存、Agent 内嵌终端视图）、**Manus/Devin**（对话交互 + 工作区看执行过程、任务卡实时状态）、**Claude Code**（执行流=日志时间线无气泡——我们终端 TUI v3 已是同款，网页执行窗口照此视觉语言）、**Slack**（频道切换=智能体切换）、**Linear**（状态徽章+活动时间线+进度）。

## 3. 复用资产盘点（v1 已盘点，v2 确认）

信封协议（sender/recipient + views 滤波）、桥接+审批流+tool_gate、计划队列、观测面（cc-activity/活动流/usage）、TerminalView/ToolCallCard/思考折叠块、@定向确定性分派链路、多端同步轮询——全部复用，零推倒。新增复用点：执行时间线渲染语言 = 终端 TUI v3 的网页化（同一批人在维护两端，视觉对齐）。

## 5. 侧边栏：智能体切换器（P1）

- **位置**：Sidebar.tsx 顶部，「新对话」按钮**上方**新增一行切换器，横向平铺 tile（图标 SVG + 名称 + 在线状态点）。
- **tile 清单（排序 小元 → CC → 自动化，用户拍板：CC 现在是主力）**：小元AI（云端，恒在线不置灰）、Claude Code（桥接在线才绿）、自动化（本地 Agent 在线才绿）。离线 tile 置灰但**可点**——进去看历史，发送时走离线提示（云端兜底/引导启动本地，现状语义复用）。
- **点击切换**：切换当前智能体 → 会话列表换成该智能体的会话（`/chat/sessions?agent_kind=`）→ 主区换窗口形态；每智能体记住 lastSid（localStorage → 后续随 prefs 上云，白名单加键）。
- **「新对话」= 当前智能体的新会话**（小元=现状普通会话；CC=新 claude 会话映射；自动化=普通会话打 automation 标）。主对话图钉/回收站逻辑不变（图钉仅小元）。
- **@ 按钮的「小窗」入口移除**（小窗机制被窗口替代）；@ 面板语义见 §6。
- **移动端**：切换器入抽屉（PlanetPage 抽屉同款模式），主区窗口全屏。
- **娱乐模式**：纯云端无本地智能体——切换器整行隐藏，只留小元（E 系列零影响）。

## 6. 对话窗口（小元AI）：委派任务卡 + 运行状态（P3）

用户要求「向其他智能体发送消息，思考和工具调用上加智能体运行状态」。设计：**委派型工具卡升级为「智能体任务卡」**——子智能体输出不再逐条进主对话，主对话只挂任务卡摘要，执行细节全在执行窗口。

**任务卡（主对话内，替代现状 delegate 内联工具卡 + @私聊气泡流）**：

- 头部：智能体身份色点+名称 + 状态徽章（排队中灰/执行中蓝脉冲/已完成绿/失败红/已停止）+ 运行时长
- 执行中：最近活动「N 秒前」（cc-activity/automation 10s 心跳数据，现状已通）+ 可选进度条（automation 心跳进度；CC 无定量进度→活动脉冲）
- 中部：执行摘要折叠——该智能体本轮的思考时长与工具调用紧凑行（复用 tool 紧凑行形态，截断）
- 尾部：**「去执行窗口看详情」按钮**（点击=侧边栏切该智能体 + 打开关联会话，复用合并框形态）
- 完成后：结果摘要（委派回传截断，现状 `_extract_tool_output`）+ 绿徽章；失败=红徽章+错误摘要+重试引导

**数据/事件双流模型**（后端协同改动核心）：

- 委派时（delegate 工具/@ 委派）：执行事件带窗口维度（目标执行窗口 session），后端路由为两路——执行窗口流（用户正开着就实时推）+ 主对话流仅任务卡状态事件（task_event：running/progress/done/failed）
- 落库双写：执行日志全量落执行窗口会话；主对话只落**任务卡摘要**一条（状态+摘要+窗口 session 引用），主对话历史回看=任务卡（不回放全量执行日志，60 条截断更省）
- 兼容：现状已存在的历史消息（sender 气泡/内联工具卡）渲染不变，新协议只影响新消息

**@ 按钮语义**（决策点 D3）：保留为「委派」快捷——主对话输入 @CC/自动化 = 本条消息作为任务委派（任务卡 + 执行窗口指令块），不再产生「@私聊会话」。**统筹模型自主委派不变**（delegate 工具），仅前端呈现升级。

**「后台执行中」指示条升级**：现状 15s 轮询 queued/running 计划；升级为按智能体分组（计划队列/CC 委派/自动化委派三源聚合），点击同样切换窗口。

## 7. 执行窗口（CC/自动化）：执行时间线（P1 壳 + P2 渲染）

「消息以智能体最舒服迅速的方式呈现」= 高密度执行日志（Claude Code 终端 TUI v3 的网页化）：

- **头部**：智能体图标+名称+在线徽标 + 最近活动「N 分钟前」（无响应超 5 分钟黄色提示，现状 #25 语义）+ 停止生成
- **时间线**（按执行单元分组，Linear 式状态色点沿左）：
  - **指令块**：发起者（你/统筹）+ 指令文本，紧凑块（灰底小圆角，非气泡）
  - **思考折叠块**：沿用「▸ 思考 (Xs) · N 次工具调用」（默认收起，流式展开）
  - **工具执行**：命令类合并 TerminalView（复用）；Read/Write/Edit 显示文件路径+变更概要（diff 详情展开，P2 先用工具卡形态，diff 高亮挂账）；普通工具紧凑 ToolCallCard 单行可展开
  - **审批卡**：保留（安全必须，Y/N 决策交互不变）
  - **结果块**：纯文本/Markdown 渲染（MarkdownContent 复用），无气泡装饰
- **操作行裁剪**：移除点赞/点踩/举报/重新生成/朗读/继续生成/追问建议；保留复制（命令/结果级，TerminalView 已实现）+ 折叠 + 停止。执行窗口**不进记忆折叠 worker**。
- **输入区**：占位「向 Claude Code 下达任务…」；用户直达该智能体（现状 @CC 私聊语义）；统筹派活同样落到此流（指令块发起者=统筹）——「受统筹监控和领导」=统筹可派活可监控（观测数据）+用户可直接指挥，两者并存
- **移动端**：全屏浮层 + 抽屉切换（复用 resolvePanel 协议）

## 8. 数据模型与后端改动（P0）

- **迁移 0031（幂等纪律）**：`chat_session.agent_kind VARCHAR(20) NOT NULL DEFAULT 'chat'`——取值 `chat`（对话）/ `claude` / `automation`。**决策点 D1 建议：扩展 chat_session，不建新表**——会话生命周期（回收站/分享/归档/侧栏排序）全复用；ai_chat 消息按 session 已落；CC 的云端 sid↔本地 claude uuid 映射（claude_sessions.json）天然不变，agent_kind 只是给会话打标。is_main 唯一约束只作用于 chat kind。
- **接口**：`/chat/sessions?agent_kind=` 过滤；createSession 带 agent_kind 打标；claude-stream 创建的会话打 claude 标（现状 claude-stream 已创建/续接 session，加标即可）；`/chat/save` 按 kind 分支（agent 会话跳过折叠 worker 触发与自动标题）。
- **折叠 worker**：`memory_fold.py` 只处理 agent_kind=chat。
- **消息落库口径**（决策点 D2 建议）：执行窗口消息全量落 ai_chat（工具事件与现状 /chat/save 同口径）——多端同步轮询、消息 id（#30）、删除/归档一套机制覆盖，不做第二套存储。
- **分享**（决策点 D4 建议）：仅 chat kind 可分享（执行日志含终端输出，分享价值低且合规面窄）；执行窗口分享按钮隐藏。
- 测试四件套：迁移 sanity + sessions 过滤 + kind 打标 + 折叠跳过（test_migrations_sanity/test_chat_* 扩展）。

## 9. 消息路由与统筹领导（P3 后端协同）

- 用户 → 小元（对话窗口）→ 统筹意图路由 → 委派（delegate 工具/@ 委派）→ 任务指令进执行窗口 + 主对话挂任务卡
- 执行 → 事件双流（§6）→ 任务卡状态推进 + 执行窗口实时时间线
- 智能体间通信：经统筹仲裁转发（v1 P2 语义保留，降优先级到 P3 之后）
- 统筹监控数据源（全现成）：cc-activity / automation 10s 心跳 / 计划队列进度 / usage
- Agent 端改动：orchestrator 委派事件带窗口 session 维度；无本地 Agent 时的云端回退→任务卡直接显示回退结果（无执行窗口可去，按钮隐藏）

## 12. 决策点汇总

**已定（用户拍板）**：侧边栏切换器形态；CC 一级智能体（独立上下文+会话，受统筹监控领导）；执行窗口不用对话式布局、无点赞点踩语音重生成；对话式 AI vs 长任务智能体二分。

**待拍板**：
- **D1 存储**：扩展 chat_session.agent_kind（**建议**）vs 新表 agent_windows
- **D2 落库**：执行窗口消息全量落 ai_chat（**建议**，多端同步/#30 一套覆盖）vs 只存摘要
- **D3 @ 按钮**：保留为委派快捷+移除小窗（**建议**）vs 彻底移除 @
- **D4 分享**：仅对话窗口可分享（**建议**）vs 执行窗口也开放
- **D5 记忆折叠**：执行窗口不进折叠（**建议**——执行日志非用户事实）
