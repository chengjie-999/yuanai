# 网页对话去群聊化：每智能体独立上下文 + 独立执行窗口（2026-11-12 立项登记）

**来源（用户原话）**：网页对话不搞群聊形式——每个智能体都是独立上下文和独立的执行窗口，各智能体之间可以相互通信。统筹和角色关系不变，统筹的云端可以监控到本地的执行进度。

**状态**：设计登记，待用户拍板分期后开工（实现是产品级重构，先行设计）。

## 1. 现状问题（为什么去群聊化）

| 问题 | 现状代价 |
|------|---------|
| 全体共用一个上下文 | 每个智能体的输出都进同一条上下文互相稀释；靠 60 条截断兜底（历史截断即丢细节） |
| 单时间线串行 | 分析、采集、自动化天然并行的工作被塞进一条流，用户分不清「谁在干什么、干到哪了」 |
| 无失败隔离 | 一个智能体卡住/报错打断整条对话流 |
| token 浪费 | 每条消息都重发全量历史；无关智能体输出占前缀缓存 |

## 2. 目标形态

```
用户（一个入口）── 统筹主对话（云端小元AI，对话即执行）
                    │  委派 / 消息传递
        ┌───────────┼───────────────┬──────────────┐
     分析窗口      采集窗口        自动化窗口      Claude Code 窗口
   （独立上下文）（独立上下文）  （独立上下文）   （独立上下文）
```

- **统筹主窗口 = 用户唯一对话入口**（角色关系不变：意图路由 → 委派 → 汇总）。用户不管理 N 个对话——子窗口是「执行详情/过程」，从统筹消息点开
- **每个智能体独立上下文**：自己的 system prompt + 自己的消息历史，互不污染；独立执行窗口 = 自己上下文里的工具调用/进度/结果可见
- **智能体间直接通信**：信封协议扩展语义——统筹给子窗口派活（recipient=target）、子窗口回传结果（recipient=orchestrator）、子智能体间经统筹转发（保持统筹仲裁，防「对讲机乱飞」）
- **统筹云端监控本地执行进度**：数据源全部现成（见 §4），右栏/窗口内进度条展示

## 3. 复用资产盘点（不推倒重来）

| 资产 | 作用 |
|------|------|
| 信封协议（sender/recipient/turn/type + views.py 七规则滤波） | **已经是独立上下文的语义基础**——每个智能体只看自己该看的消息，v2 只需加「窗口/通道」维度 |
| 云端/本地桥接 + 审批流 + tool_gate | 零改动 |
| 计划队列三表 + plan_executor | 统筹派活 → 独立窗口执行的现成载体；步骤进度即窗口进度 |
| 观测面（cc-activity/活动流/usage） | 「统筹监控本地执行进度」的数据源已全通（终端 v3.2 右栏是桌面侧先例） |
| 工具调用卡/思考折叠块 | 子窗口内复用渲染 |
| @ 定向（target_agent 确定性分派）+ dmTargets 小窗 | 已有一对一定向的执行链路，是「独立窗口」的雏形 |

## 4. 设计要点（三块）

### 4.1 窗口模型
- 会话模型升级为「一主多子」：主会话（统筹对话，现状 ai_chat 不变）+ 子窗口 = 主会话下挂的独立上下文（新表 agent_windows：window_id/session_id/agent_role/status/独立消息数组），还是沿用多会话 + 关联字段——**决策点 A**（建议新表：子窗口生命周期短、要挂进度状态，混进 ai_chat 会污染主对话列表与折叠 worker）
- 子窗口创建时机：统筹委派工具调用时自动开窗（用户不手动开）；@ 定向也走窗口语义

### 4.2 消息路由
- 信封加 `window` 维度；views.py 滤波按窗口 + 收件人双层
- 智能体间通信 = 统筹仲裁的消息转发（子→子必须经统筹，防语义失控）；统筹视角 = 各窗口摘要 + 全量可钻取

### 4.3 前端布局
- 桌面：统筹对话居中 + 右侧/底部子窗口栏（标签页，每个=执行详情：上下文消息 + 进度条 + 结果）；消息里「打开窗口」按钮（合并框形态沿用）
- 移动：子窗口 = 抽屉/全屏浮层（复用 resolvePanel 浮窗协议），不搞分栏
- 进度：窗口头部进度条（自动化 10s 心跳、计划步骤进度、脚本 registry 进度三源合一）

## 5. 分期建议

- **P0 窗口模型 + 独立上下文（核心）**：agent_windows 表 + 路由层（信封 window 维度）+ 后端窗口 CRUD/进度端点；统筹委派自动开窗，窗口内独立消息流
- **P1 前端窗口 UI**：桌面标签页栏 + 移动浮层；窗口进度条；「打开窗口」合并框入口
- **P2 智能体间通信语义**：统筹仲裁转发 + 窗口摘要进统筹上下文（省 token 的关键一步：统筹只见摘要不见全量）
- **P3 统筹监控本地进度**：窗口进度聚合 + 主对话「后台执行中」指示升级（现有 15s 轮询指示条扩展）

## 6. 风险与决策点（待用户拍板）

- **决策点 A**：子窗口存储（新表 agent_windows vs 多会话关联）
- **决策点 B**：子窗口历史是否落主对话折叠 worker（建议：窗口消息不进记忆折叠，只折叠统筹视角摘要）
- **决策点 C**：Claude Code 窗口边界（本机桥接已有独立会话，窗口=纯 UI 容器即可）
- 移动端多窗口复杂度（抽屉方案先行）
- 与 #30 消息 id 架构债的顺序关系（建议窗口模型 P0 与消息 id 独立可并行，但前端合入时统一）
- 工作量预估：P0 云端+Agent（3-5 天）+ P1 前端（3-5 天），属大立项
